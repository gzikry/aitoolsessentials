    Overview

    CCC (Claude Command Center) is a local dashboard for people running several coding agents at once. Instead of owning execution, it reads each engine's on-disk state as the source of truth, so a session you started in a terminal, resumed by hand or launched headless outside the dashboard still shows up on the board - that is the difference between a dashboard and a second place you have to remember to work from. On top of the board it adds a needs-attention lane that flags sessions ending on a real question, a per-session context meter, plan-usage and rate-limit projections, a Kanban with a project tree and an infinite Flow canvas, group chats between agents, a work queue with verify-to-close receipts, git worktrees per task, and an optional fallback that keeps a limit-hit session running on a $0 model. The stack is deliberately plain: a stdlib-only Python server bound to 127.0.0.1 and a no-build vanilla-JS UI, with readable JSON state under ~/.claude/command-center/. Claude Code is first-class; Codex, Cursor, Antigravity, Kilo Code, Kimi Code, OpenCode and Devin spawn and ingest with documented gaps. Version 5.39.0 shipped 2026-10-18 and the repository was pushed the same day this review was written.

    Key features

    • One local board for every coding-agent session on the machine, read from each engine's on-disk state rather than only from sessions the dashboard spawned
    • Needs-attention lane for sessions that end on a real question, including plain-prose ones, with desktop notifications on macOS
    • Per-session context meter with warning and danger levels and one-click compact
    • Usage windows and rate-limit pace projections for Claude plans and Codex limits
    • Optional fallback of a limit-hit session to a local free-model router, with deliberate per-session choice rather than automatic spend
    • Kanban stage columns (Working, Review, a testing column, Verified, Archived), a nestable project tree, and an infinite zoomable Flow canvas with edges
    • Split pane for two transcripts side by side, each with its own input bar, plus search and ask across session history with citations back to the source session
    • Group chats that let several agent sessions share a thread and ping each other in turn, with no orchestrator to write
    • Work queue with claim, fix, verify and close lifecycle, a queue-health watcher, and receipts that close GitHub issues with a commit-SHA comment
    • One-click fresh git worktrees per task, an annotate mode that turns a clicked element into a queue ticket, and an optional Vercel watch for failed production deploys
    • Responsive mobile UI with one-button Tailscale setup and a QR code, or an opt-in outbound-only CCC Cloud relay
    • ccc CLI for the fleet from a terminal: sessions, models, spawn, send and ask, with sessions addressable by id or name fragment
    • Stdlib-only Python server bound to 127.0.0.1 with a no-build vanilla-JS interface, and human-readable JSON state under ~/.claude/command-center/

    Use cases

    • Seeing every coding-agent session on one machine, including ones started or resumed by hand in a terminal
    • Spotting the agent that asked a question forty minutes ago, or the one whose context window is nearly full
    • Arranging a fleet of sessions by stage - Working, Review, a testing column, Verified, Archived - instead of one flat list
    • Typing a follow-up into a dormant session from the browser and having it resume to receive it
    • Running a queue of tickets overnight with agents that claim, fix, verify and close work with a receipt

    Pros

    • The telemetry claim survives reading the code rather than only the copy: ccc_server/fleet_jobs.py documents the complete beacon payload field by field (schema_version, version, platform, and two booleans derived from the local last-run date), lists what is never sent - no install id, no prompts, transcripts, tool calls, session counts, token counts, repo paths, hostname, git config or IP - and CCC_TELEMETRY_DISABLED=1 is a hard kill switch that stops every byte rather than a preference stored somewhere
    • The richer opt-in daily ping was retired on 2026-09-28 and the code says so in the same comment block, with the reason (the consent banner was not worth the number, and active_seconds_today was broken by construction) - a vendor deleting its own telemetry surface and documenting why is rare
    • Site analytics are deliberately configured rather than left on defaults: PostHog is initialised with persistence memory, person_profiles identified_only, and autocapture, pageleave, session replay, surveys, dead clicks, performance, heatmaps and exception capture all off, with respect_dnt on, so pageviews and the download button are the whole measurement
    • The vendor publishes a threat model instead of a security page of adjectives: SECURITY.md names the absence of authentication, the loopback-only bind, the same-origin POST check, the fact that headless sessions run with --dangerously-skip-permissions, and that state files are created with the default umask (world-readable on macOS) with chmod 700 recommended on a shared machine
    • Data boundaries for the account-based surfaces are written down with periods rather than adjectives: CCC Cloud stores your email and consent records, paired devices as opaque IDs with a hashed credential, notification records for 30 days and a per-device audit log for 90 days, never uploads transcripts, paths or code, and exposes a closed five-capability list with no generic shell execution
    • Engine support is stated with its gaps instead of implying parity - Claude Code first-class, the other seven spawning and ingesting 'with documented gaps' - and the site lists the limitations of its own comparison table
    • The core mechanism is the interesting part: because each engine's on-disk state is the truth, a session survives closing the dashboard and a hand-resumed session is not invisible, which is the failure mode of orchestrators that want to own execution
    • Real distribution rather than a launch-page promise: 202 stars and 25 forks on a repository created 2026-04-13, a 3.6 MB notarized and Apple-signed DMG that resolves, a working Homebrew formula, a read-only demo on seeded data, a full changelog, and independent third-party write-ups plus a YouTube walkthrough
    • Free with no upsell ladder: no account, no seat count, no feature held behind a paid tier, and every release becomes MIT-licensed after two years
    • Bounded cost behaviour in the free-model path: a spawn that cannot reach the local free-model router refuses to start rather than silently billing, and the vendor documents that free runs strip ANTHROPIC_API_KEY, CLAUDE_CODE_OAUTH_TOKEN and CLAUDE_CODE_SESSION_KEY from the child process

    Frequently asked questions

    How much does CCC cost?

    Nothing. The local dashboard is free at $0 with no tiers, no paid plan and no account, and the license (FSL-1.1-MIT) permits use, copying, modification and redistribution for any purpose other than building a competing product, with each version converting to MIT on its second anniversary. The optional CCC Cloud phone relay is account-based, and no price for it appears on any page fetched during this review.

    Is CCC really local, and what does it send home?

    The app is local: it runs a stdlib-only Python server bound to 127.0.0.1 and keeps readable JSON state in ~/.claude/command-center/. It does send one anonymous beacon at most once per day containing the schema version, the app version, the platform string and two booleans saying whether this is the first beacon of the ISO week and of the month - no identifier, no prompts, no transcripts, no paths, no token or session counts. CCC_TELEMETRY_DISABLED=1 turns it off entirely. The website itself loads cookieless PostHog with memory-only persistence and no autocapture.

    Can I run it on a team or a shared machine?

    Not safely as a shared service. The server has no authentication and no per-user accounts: anything that can reach the port can spawn sessions and, because headless spawns use --dangerously-skip-permissions, can run commands as your user. The vendor's advice is loopback only, or a trusted private network such as Tailscale, and chmod 700 on ~/.claude/command-center/ on a shared machine. For a team, treat it as a per-developer tool, not a control plane.

    Which coding agents does it actually support?

    Claude Code is first-class. Codex, Cursor, Antigravity, Kilo Code, Kimi Code, OpenCode and Devin spawn and ingest with documented gaps, and the site says so rather than implying uniform support. The macOS app is the most complete path; Linux is headless and Windows installs through a PowerShell script.

    Do I need to hand over my Claude subscription or API key?

    No. CCC runs your installed claude command, which reads its own login, and the vendor's docs/tos-boundary.md says the login token is never sent to the free router, another provider, CCC telemetry or another machine, and is never copied between machines. Free-model spawns strip ANTHROPIC_API_KEY, CLAUDE_CODE_OAUTH_TOKEN and CLAUDE_CODE_SESSION_KEY from the child process first.
