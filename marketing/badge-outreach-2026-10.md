## Defect found and fixed in this pass

Batch 1 shipped with a personal name in the sign-off (`Best, <first name> <surname>`), against
the house rule that outbound vendor mail closes as AIToolsEssentials only. Confirmed by reading
the nine Sent-Mail records, not a draft. Root cause: the generated vendor note in the kit ended
on the "reply with the official pricing URL" line with **no sign-off at all**, so the composing
run added one and used the person's name.

Fixed at the source rather than in the sent mail (a delivered message is not re-sent to correct a
header or signature):

- `scripts/generate_outreach_kit.py` `_vendor_note()` now ends every note with
  `— AIToolsEssentials` + the site URL.
- `_markdown()` now prints the rule at the top of the kit: outbound mail signs as
  AIToolsEssentials, never a personal name or personal address in the body.
- The script gained an `if __name__ == "__main__"` block; before this it had none, so running it
  directly silently did nothing and only `daily_content_update.py` could regenerate the packet.

`validate_site.py` already fails the build on the personal name in any `.md`/`.json` outside
`admin/`, which is why this file and the kit describe the defect without reproducing it.
