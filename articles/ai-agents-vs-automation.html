    Buying question

    Do you need an AI agent, or just automation?

    The difference is who picks the next step — and that one choice decides cost, auditability, and how badly a bad run can go.

    Quick answer

    Automation runs steps you defined in advance. An agent gets a goal and tools, then chooses the next step at run time. If you can draw the flowchart, buy automation: cheaper, easier to audit, fails visibly. If the sequence depends on judgment you cannot enumerate, an agent fits — and it can also do something you did not ask for.

    The difference is who picks the next step

    In a workflow automation, the order is fixed at build time: this trigger fires, this step reads the form, that step writes the row. Each step has a defined input and output, so a break points at the step that broke. In an agent, the model gets a goal and tools, then decides what to call next — it may loop, re-read, or chain several actions before reporting back, on every run.

    That difference explains why the marketing has converged: step-based platforms sell model-driven steps, and agent frameworks ship scheduling and retries. The brand name no longer tells you which you are buying — ask whether the sequence is settled at build time or run time.

    When automation is the better buy

    Most processes people want to agentify are flowcharts: a form becomes a row, a row becomes a task, a task becomes an email. That is deterministic, repetitive work — where a fixed sequence wins:

    • You can test it exhaustively. Ten runs of the same input should produce the same output; when they do not, it is a bug, not an opinion.
    • Cost is predictable. Pricing is usually per task or per operation, which you can estimate from volume.
    • Failure is loud. A broken step raises an error and stops. An agent that misreads the situation can keep going.

    Make, Zapier, and n8n are the mainstream choices, and our automation category guide compares them on task counting, self-hosting, and how much logic you can express without code. Browse AI is the narrower version for watching pages and extracting changes.

    When an agent earns the extra risk

    An agent is worth considering when input is unstructured and the path varies: a support request that might be answered from the help centre, the billing system, or last week's ticket; a research task where the next question depends on the last answer; a request like "find a time and book it" that touches three systems and has to handle a conflict.

    In our directory that shape appears a few times: Hermes Agent as an open-source framework with tools, skills, memory, and scheduled routines; OpenClaw as a self-hosted gateway connecting channels, tools, and model providers; CustomGPT.ai for document-grounded assistants; Robylon for support agents that act through APIs rather than only answering. The Hermes Agent vs OpenClaw comparison covers the self-hosted end of that list.

    The value and risk come from variation. If your task does not vary much, you are paying for judgment you do not need.

    The three costs people forget

    Supervision. Someone has to review what the agent did, especially anything that sends, pays, or deletes. That reviewer is a real cost, and the first thing to disappear when a team gets busy.

    Iteration. Prompts, tool descriptions, and thresholds change, and behavior drifts with model updates. An automation keeps doing the same thing; an agent needs re-grading.

    Blast radius. Permissions decide how bad a wrong decision gets. Read-only access that misreads a request wastes minutes; send-and-delete access creates work for someone else.

    Test one workflow before you buy either

    1. Pick one recurring task with an output you can grade — a drafted reply, a filled row, a booked meeting.
    2. Write the ideal steps by hand first. If you cannot describe what "done" looks like, there is nothing to measure against.
    3. Run ten real cases, including three messy ones: a vague request, a missing field, and one that should be refused.
    4. Count four outcomes: correct without edits, correct after edits, wrong, and "did something you did not ask for". The last category decides whether you can leave it running.
    5. Decide against the error you can tolerate, not the best demo. Eight right out of ten is fine for drafting, unacceptable for refunds.

    Permission is the real gate

    Agents are defined by their access. Every tool you connect is a credential, and every credential decides what a wrong answer reaches. Before connecting anything, settle scope, whether it can write as well as read, where the run log lives, and who can stop it. The data-connection checklist covers that conversation; the vendor questionnaire covers what to send the seller.

    A rule that survives the hype

    Automate the steps you can name. Give an agent the judgment you are prepared to review. If you cannot say what a correct run looks like, you are not ready to hand over the keys.

    Frequently asked questions

    Is an AI agent just a chatbot with tools?

    Not quite. A chatbot with tools answers when you ask. An agent is given a goal, decides which tools to call and in what order, and may take several actions before returning. The difference is autonomy over sequence.

    Do agents replace workflow automation?

    Rarely. Most processes stay cheaper and safer as fixed steps, because fixed steps are testable and stop when they break. Agents handle the parts that vary, usually a minority of the volume.

    What is the smallest safe first agent project?

    Something read-only with a human in the loop: gather, summarize, or propose a draft. Keep write access off until you have watched it fail on real cases.
